# Snapmaker Studio — interactive user guide

A static, click-through guide for **Snapmaker Studio v1.5.0**: twelve lessons from installing Studio to checking a sliced
job, with real screenshots, numbered hotspots, an enlarged-image viewer and small example walkthroughs. It needs no
backend, no account, no Tauri and no printer, and it runs from any static host (or from this folder's preview server).

> Snapmaker Studio is an independent open-source project — not affiliated with or endorsed by Snapmaker.

## What is in this folder

```
site/guide/
  public/                  ← the website. This folder is what you deploy.
    index.html             ← GENERATED by tools/build.mjs (committed, so reviewers can open it)
    assets/guide.css       ← styles (brand tokens, light/dark themes)
    assets/guide.js        ← one lesson at a time, progress, viewer, hotspots, walkthroughs (no network access)
    assets/theme-init.js   ← applies the saved theme before first paint
    assets/md.js           ← tiny inline-markup renderer shared by the build and the page
    assets/img/            ← screenshots (captured from the real app) — see "Screenshots"
    assets/brand/          ← the approved Studio mark and favicon, copied from docs/brand
  content/
    lessons.json           ← the lessons (edit this to change words)
    shots.json             ← each screenshot's alt text, caption and hotspot explanations
    geometry.json          ← GENERATED: where each hotspot sits, as percentages of the picture
  tools/                   ← build, preview, capture and verification scripts (Node, no runtime dependencies)
  deploy/                  ← sample deployment files (nothing here runs automatically)
  EVIDENCE.md              ← which verified screen or source backs each documented workflow
```

## Preview and build

Requires Node 18 or newer. Nothing to install to build or preview.

```bash
cd site/guide
node tools/build.mjs        # validate content and regenerate public/index.html (fails on any problem)
node tools/serve.mjs        # preview at http://127.0.0.1:4173/  (Ctrl+C to stop)
```

`node tools/build.mjs` refuses to build if a lesson is missing a field, a screenshot or its alt text is missing, a
hotspot has no captured position, two hotspots overlap, a walkthrough names the wrong circle number, or the text contains
something that looks like an IP address, a local path, an internal tool name or a guarantee claim.

## Checks

```bash
node tools/check.mjs        # static checks: links, ids, alt text, no third-party requests, strict-CSP readiness, colour contrast
node tools/check.mjs --online   # also confirms every external link answers
node tools/e2e.mjs          # browser checks (needs Microsoft Edge or Chrome and `playwright-core`)
node tools/e2e.mjs --shots ../../some/folder    # also saves screenshots of the finished guide
```

`tools/e2e.mjs` serves `public/` with a strict Content-Security-Policy and, at desktop (1280 px) and phone (390 px)
widths in both themes, checks every deep link, Next/Back/browser history, saved position and **Start again**, the theme
switch, the mobile lesson menu, the screenshot viewer (focus in, Escape out, focus restored), every hotspot, every
walkthrough from start to finish, missing images, horizontal overflow and console errors. A separate no-JavaScript run
checks that every lesson is readable on one page. If `playwright-core` is not installed here, the script falls back to
the copy in `tools/acceptance/`; otherwise run `npm install` in this folder.

## Deploy

`public/` is plain files with relative URLs, so it works at the root of a domain or in a sub-folder. There is no build
step on the server; commit the regenerated `public/index.html` and publish `public/`.

* **GitHub Pages** — publish the `site/guide/public` folder with the official Pages actions. `deploy/github-pages.yml.example`
  is a ready workflow; copy it to `.github/workflows/` and enable Pages (Settings → Pages → Source: GitHub Actions) to start.
  Nothing in this repository deploys the guide until you do that.
* **Netlify / Cloudflare Pages / any static host** — publish directory `site/guide/public`; no build command is needed (or
  use `node site/guide/tools/build.mjs`).
* **Recommended headers**: `deploy/security-headers.txt` (a strict Content-Security-Policy that the guide is tested under,
  plus the usual hardening headers). The guide loads no third-party script, font, image or stylesheet.

After you choose a host, set the link used inside Studio's **Help** and **Get Started** pages in one place:
`desktop/src/lib/guide.ts` (`USER_GUIDE_URL`). It currently points at `https://dvopenlabs.github.io/snapmaker-studio/`
(the address GitHub Pages would give this repository) and will show a "not found" page until the guide is deployed there.

## Maintain it

* **Change wording or add a step** — edit `content/lessons.json`, run `node tools/build.mjs`. Inline markup: `**UI label**`
  (always the exact label shown in Studio), `` `code` ``, `*emphasis*`, `[text](https://…)` or `[text](@key)` where `key` is
  in `links` (so a URL lives in one place).
* **Change a hotspot's explanation** — edit its `text` in `content/shots.json`, rebuild. Hotspot numbers are the order in
  that list; a walkthrough step that says "circle 3" is checked against it by the build.
* **Add or move a hotspot, or refresh a screenshot** — edit `tools/spec.mjs` (the target is a Playwright locator for the
  control) and run the capture below.
* **New Studio release** — set `site.guideVersion` and the wording in `content/lessons.json`, recapture, run the checks,
  and walk the guide against the new build. Hashes and installer names are never copied into the guide: it links to
  `docs/RELEASE_METADATA.md`, which stays the single source.

### Screenshots

Every screenshot is captured from the real Studio interface, with example files from `/examples` and `tools/fixtures.py`.

```bash
node tools/capture.mjs                  # all dev-UI screenshots (starts a disposable engine, the Studio web UI and a
                                        # made-up Spoolman on 127.0.0.1:7912; needs Python, Node, Edge/Chrome)
node tools/capture.mjs --only home,fidelity
pwsh -File tools/capture-installed.ps1 -Installer <release .exe> -Sha <sha256> -SourceVersion 1.5.0
                                        # the screenshots that need the INSTALLED app (handoff.png), inside the
                                        # repository's isolated test harness; never presses "Open in Snapmaker Orca"
```

The capture scripts never connect to a printer, a slicer or the internet; they stop every process they start. Before each
screenshot they replace any local path with `<folder>`. Each run rewrites `content/geometry.json` for the shots it
captured, so hotspots stay aligned. Review new screenshots for private data before committing (this guide's captures use
only synthetic example files and made-up spools).

Studio's own window is captured in its dark theme. The guide itself has both themes. Screenshots of the finished guide are in `evidence/screenshots/`.
