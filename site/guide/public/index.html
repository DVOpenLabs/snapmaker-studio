What to do

  1. Open This print for the whole job, or Compatibility for the full list (Open the full checks links there).
  2. Read Object placement first: it is the one finding with a fix.
  3. Skim the cards. For each, read the label, then its Do this: line. Open Technical detail only if you are curious.
  4. Make a short list: confirmed problems, things to check in Orca, things Studio cannot tell.

You are done when

  • You can say which findings are facts about the file and which are gaps.
  • You know whether the next step is a fix in Studio (stage 3) or a job for Orca.

If it looks different

The findings say “Invalid value for …”. Is my model broken?

Usually not. The text says the model may be fine and the project settings are for another printer.

Cards show “Checking…” for a while.

Studio first tries to reach a printer. When none answers, the cards switch to Printer not found and Studio can’t tell.

My findings differ from the example.

They describe your own file. The labels mean the same thing.

Studio can’t tell

“Studio can’t tell” means Studio has no way to read the fact from your printer. It does not mean your printer cannot do it.

Your files are safe

The checks are read-only. Studio never edits your file while diagnosing it.

Misplaced, or too big to fit?

Three real projects, three different placement messages. Read what Studio shows, then decide what you would do. The numbers and wording are copied from Studio v1.5.0 run on the guide's example files.

Worked example (the interactive version needs JavaScript):

Case 1 — one small object, off to one side

  • Studio says: 1 object is outside the U1's printable area.
  • Object 2 · 20 × 20 × 20 mm — Hangs 55.0 mm past the right edge.
  • Studio offers a button: Move onto the plate (saves a copy).

What is the right next step?

  • Press Move onto the plate, then prepare the moved copy. Best answer. Right. The object is small and simply sits too far to the right. One shift of the whole layout brings it on, and Studio re-checks the file it wrote. Your original is not touched.
  • Rescale the object in Snapmaker Orca. Not this. Nothing here says the object is too big: it is 20 mm and the plate is far larger. Rescaling would change your model's real size for no reason.
  • Ignore it: 55 mm is not much. Not this. Distance does not matter: Orca will still say the object is out of bounds. A small part can pass every size check and still land off the plate, which is why Studio names the edge and the distance.

Case 2 — one long bar that hangs off both ends

  • Object 1 · 320 × 20 × 20 mm — Hangs 1.0 mm past the left edge and 50.0 mm past the right edge.
  • Studio says: Moving the objects as one piece would not bring them all on, so Studio will not guess. Open the project in Snapmaker Orca and use Arrange.
  • There is no Move button.

Why is there no Move button, and what do you do?

  • The object overhangs both the left and the right edge, so it is longer than the plate. No position works; Studio will not guess. Change the model in Orca. Best answer. Right. Overhang on two opposite edges plus a 320 mm length tells you the object itself is longer than the plate, so moving it cannot help. Studio's own advice is to open the project in Snapmaker Orca; if the part really is longer than the plate you will also need to resize, rotate or split it there. Studio does not edit your model.
  • Look harder for the Move button; it is probably hidden. Not this. There is none. Studio offers the move only when one shift brings every object on the plate. When it cannot, it says so instead of half-fixing the project.
  • Use Scale Doctor to shrink it. Reasonable, with a catch. Possible, if you really want a smaller part. Scale Doctor previews a uniform resize, and writes a scaled copy only for an STL; for a 3MF you resize in Orca. Shrinking changes what you print, so make it a deliberate choice, not a way to silence a warning.

Case 3 — two small cubes far apart

  • Object 2 · 10 × 10 × 10 mm — Hangs 35.0 mm past the right edge. (Object 1 is on the plate.)
  • Studio says the same thing as in case 2: Moving the objects as one piece would not bring them all on, so Studio will not guess.
  • There is no Move button.

Each cube is tiny. What is the real problem?

  • The objects are too far apart: together they are wider than the plate. One shift cannot bring both on, so rearrange them in Orca with Arrange. Best answer. Right. Neither cube is big; the layout is. Moving them as one piece would push one off the other side, so Studio stops. Arrange in Snapmaker Orca can bring the objects closer together.
  • The cube is too big for the U1. Not this. The cube is 10 mm. Compare the object's size with how far it hangs over: it is the distance between objects that is the problem.
  • Press Move onto the plate anyway. Not this. The button is not offered here, on purpose: moving the whole layout could not bring both cubes on.
  • What to take from it
  • Check the size of the object against the overhang: a small object that hangs off one edge is misplaced.
  • Overhang on two opposite edges means the object is longer than the plate.
  • If Studio offers Move onto the plate, one shift is enough. If it does not, it will say so and send you to Orca's Arrange.

Assigning a material is not loading it

You open a project with Project Materials. For slot 1 you pick a spool from your inventory and confirm an installed Orca preset, tick Remember this mapping, and press Prepare with these choices. Tick everything Studio did.

Worked example (the interactive version needs JavaScript):

  • Wrote the spool's colour into the new copy. Yes, Studio does this. Yes. The review says Colour changed to Red: the chosen spool's colour is written into the new copy.
  • Named the installed preset in the new copy. Yes, Studio does this. Yes. The review shows the slot mapped to the preset you confirmed, so Orca opens the copy with that preset name.
  • Saved the mapping on this computer, after the copy was written. Yes, Studio does this. Yes, because you ticked Remember this mapping. It is saved only after Prepare succeeds, and it is checked again every time it is used.
  • Loaded that filament into a toolhead. No, Studio does not do this. No. Studio never loads, swaps or changes spools. Putting the right filament in the right toolhead is your job at the printer.
  • Changed the spool in your Spoolman, SpoolEase or Bambuddy inventory. No, Studio does not do this. No. Studio only reads a provider; it never writes to it.
  • Wrote the spool's ID or remaining weight into the project. No, Studio does not do this. No. The review says spool details are not read from the file and that Studio never writes them into the project.
  • What to take from it
  • Studio can put a colour and a preset name into a new copy. It cannot put filament into a toolhead.
  • The U1 has four toolheads. Studio plans around them, and then you load the colours in the order the project lists them.
  • Your spool inventory is read, never changed.

What to do

  1. If Object placement offers Move onto the plate (saves a copy), press it. Studio writes …_placed_U1.3mf next to your original.
  2. Press Open a model and choose that moved copy. (The move and the U1 preparation are separate actions.)
  3. Leave Preserve creator settings selected unless you have a reason, then press Prepare U1 copy.
  4. Optional, if you track spools: pick a spool and an installed preset for each colour under Project materials, press Review & prepare, read the review, then Prepare with these choices.

You are done when

  • U1 copy created — review setup before slicing, saying your original file is not modified.
  • New files beside your original, for example …_placed_U1_SnapmakerU1.3mf. You may also see a .orig.3mf snapshot Studio keeps next to a prepared copy.
  • Opening the prepared copy, Object placement says the object sits inside the printable area.

If it looks different

There is no Move button.

Either every object is already on the plate, or one move cannot fix the layout. Work through the placement example above.

The prepared copy still shows warnings.

Studio prepares the file for the U1; it does not fix every setting. Read Your fix plan: each step is marked Do this in Studio or Do this in Orca.

Prepare stopped appears with Project Materials.

Two slots share one preset but the project declares different vendors or types for them. Choose a different preset for one slot; Studio does not edit the project for you.

Important

Move onto the plate only changes where objects sit. To get a U1 copy that is also on the plate, prepare the moved copy. Preparing the original on its own does not move anything.

Your files are safe

Your original is never modified. Every action here writes a new file.

Read a preparation report

After preparing, Studio lists what it did. Sort these real lines from a prepared copy of the example project into the section they appear under, and see what each one asks of you.

Worked example (the interactive version needs JavaScript):

  • Printer identity changed to Snapmaker U1 → Adjusted for U1 compatibility. Adjusted. The copy now says it is for a U1. You do not need to act on it; it is why Orca can open the file with U1 settings.
  • 533 creator settings kept → Kept from the original file. Kept. These are the creator's own print settings, carried over because you chose Preserve creator settings. Nothing to review unless you want to change them in Orca.
  • nozzle_type: stainless_steel → hardened_steel → Adjusted for U1 compatibility. Adjusted. A before → after pair under Adjusted for U1 project compatibility is a real change Studio made. Skim Before and after for any line that surprises you.
  • 24 optional recommendations available, including tower placement and tower wall type → Optional recommendation, not applied. Not applied. Recommendations change nothing unless you choose them, for example with Prepare another copy with recommended settings.
  • Turn on supports — Do this in Orca → A step for you in Snapmaker Orca. Yours. Studio cannot choose supports for you; its fix plan marks this step Do this in Orca, so review it there before slicing.
  • What to take from it
  • Kept and not applied need no action. Adjusted is worth a skim. Do this in Orca is your job.
  • Anything Studio could not identify in both files is listed as unverified rather than assumed fine.
  • Your original is never modified: Return to the original points Studio back at it.

  1. After preparing, scroll to What survived preparing this copy and note the counts.

  4. Read Your fix plan: anything marked Do this in Orca is for the next stage.

You are done when

  • You can name what Studio changed and what it left to you.
  • You know where Return to the original is, and that the original was never changed.

What to do

  1. On the prepared result, press Open in Snapmaker Orca (or Copy path).

Unknown, or a confirmed problem?

Studio's checks of a sliced job come in different strengths. These lines come from two real checks: one job sliced for a U1, one sliced for a different printer, both checked with no printer connected. Decide how sure Studio actually is.

Worked example (the interactive version needs JavaScript):

  • Sliced for a different printer — “Toolpaths, temperatures and machine commands are generated for one specific machine.” (the job names a Bambu Lab printer) → Confirmed in the file. Confirmed. The job's own header names another printer, so Studio does not need a printer connected to know this. Action: re-slice the model in Snapmaker Orca with a U1 profile.
  • Tools this job needs — “Studio cannot confirm your printer has the toolheads this job expects.” → Unknown. Unknown. Studio would have to read your printer to know. This is not a problem found; connect the printer in Printer Hub, or check yourself.
  • Nozzle size — “Studio has no way to see which one is installed.” → Unknown. Unknown. Check the nozzle on the printer. You can also record what is fitted under Settings → Nozzles.
  • Studio cannot tie this job to your project — “nothing in either file identifies the model.” → Worth settling first. Worth settling. Studio cannot tell whether this is the slice of the project you checked, so it asks you to be sure you picked the right file.
  • Sliced for the machine Studio prepares for — “The job's commands were generated for a Snapmaker U1.” → Looks right. Looks right. This appears when the job names a U1. Still advice, not a promise that the print will succeed.
  • What to take from it
  • “Studio can’t tell” is not “incompatible”. It means Studio has no way to read it, usually because no printer is connected.
  • A problem is confirmed only when the evidence is in the file Studio can read, such as the printer named in the G-code.
  • For unknowns, either connect the printer or check them yourself. For confirmed problems, fix the cause in Orca and slice again.

What to do

  1. Open After Slicing (Advanced sidebar, More tools, or stage 3 of This print).
  2. Optional: type the folder where Orca saves exports and press Watch this folder. Studio looks only while this page is open.
  3. Otherwise drag the .gcode onto the window or paste its full path under Open the G-code your slicer produced, then press Check this job.
  4. Read Ready to send?, then each finding. Sort them into confirmed, worth settling and unknown.
  5. Read What the printer will actually do and What to load (what each slot needs).

You are done when

  • You know which findings are facts about the file, and which are gaps only a printer reading can fill.
  • You can say what you will do about each: re-slice, check yourself, or connect the printer.

If it looks different

Nothing appears in the watched folder.

Check it is the folder Orca exports to, and that this page is open. You can always paste the file's path.

Studio says “that file does not exist”.

The path is wrong. Copy the full path of the exported .gcode again.

Many items say “Studio can’t check this”.

That is what honest looks like with no printer connected. Connect the printer (see the task) or check those items yourself.

Studio can’t tell

Studio reads the file, not the world. With no printer connected it cannot tell which tools are present, whether slots are loaded, whether the bed matches or which nozzle is fitted.

Your files are safe

Studio reads and never changes your G-code, and it never sends anything on its own. Printing starts only when you start it on the printer or confirm it in Printer Hub.

Not covered here

This guide has no screenshot of a connected printer: no printer was contacted while it was written.

Install and open Studio

Use this when: You have not installed Studio yet. If it is already installed, skip this: the example starts from opening a file.

Before you start

  • Windows 10 or 11 (64-bit), or Linux x86_64 with a desktop. Ubuntu 22.04 and 24.04 are the systems the Linux package has been checked on. macOS is not supported.
  • Nothing else to install: no Python, Node.js or Rust. There is no account.

Steps

  1. Open the official Releases page (opens in a new tab) and download the Windows installer (Snapmaker.Studio_<version>_x64-setup.exe) or the Linux .deb. Download only from that page.
  2. Check the download against the SHA256 in RELEASE_METADATA.md (opens in a new tab); that file is the one place current hashes are kept.
    • Windows (PowerShell): Get-FileHash -Algorithm SHA256 .\<installer>.exe
    • Linux: sha256sum <file>.deb
    • If the values differ, delete the file and download it again.
  3. Windows: run the installer. It is not code-signed yet, so SmartScreen may say Unknown publisher. Once the hash matches, choose More info → Run anyway, then start Snapmaker Studio from the Start menu. More: Windows install guide (opens in a new tab).
  4. Linux: sudo apt install ./<the .deb file name exactly as shown on the Releases page>, then start Snapmaker Studio from your application menu or run snapmaker-studio-desktop. More: Linux install guide (opens in a new tab).

You are done when

  • Studio opens on Home, with the version v1.5.0 in the status bar and Local-only · nothing leaves your network in the footer.
  • There is nothing to sign in to.

If it looks different

Windows says “Windows protected your PC”.

Expected for an installer that is not code-signed yet. Continue only after the SHA256 matches and you downloaded it from the official Releases page.

The hash does not match.

Do not run the installer. Delete it and download it again from the official Releases page.

Studio looks different from this guide.

This guide describes v1.5.0. Check the version at the bottom of the Studio window; the release notes (opens in a new tab) say what changed.

Not covered here

Linux support is verified by automated installs on clean Ubuntu 22.04 and 24.04 systems. Other distributions and real desktops have not been recorded yet; see the Linux install guide (opens in a new tab).

Your files are safe

Uninstalling does not delete your project data. On Windows it lives in %LOCALAPPDATA%\SnapmakerStudio.

Before you start

What to review in Orca before slicing

Use this when: The copy is open in Orca and you are about to slice.

Before you start

  • The prepared copy open in Orca.

Steps

  1. The printer is Snapmaker U1.
  2. The filaments and colours match what you will load, toolhead by toolhead.
  3. Every object is on the plate. Use Arrange if unsure; Studio does not verify spacing between objects.

You are done when

  • You have an exported .gcode file and know what you checked.

That can happen when the creator's tuned settings are kept. Review the settings before slicing.

Connect your printer

Use this when: You want live status and comparisons against your actual U1.

Before you start

  • Your U1 is on, and on the same network as this computer.
  • On the U1's touchscreen, Advanced Mode is on under Settings → Maintenance; Studio's own message says the network interface only opens once it is.

Steps

  1. Open Printer (Simple) or Printer Hub (Advanced).
  2. Under Connect to your U1, type the printer's network name (the field starts with U1.local) or IP address and press Connect, or press Auto-detect my U1.

  4. Read what Printer Hub reports. Anything the printer does not tell Studio says so, for example Nozzle sizes: not reported.

Nothing answered at that address. Check the printer is on and on this network, the address is right, and Advanced Mode is on under Settings → Maintenance on the touchscreen.

Auto-detect finds nothing.

Type the name or IP address and press Connect.

Your files are safe

Monitoring is read-only. Studio never starts a print by itself.
