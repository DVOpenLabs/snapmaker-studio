# Packaged Windows validation of the viewer

What ran: the Windows installer built by CI (`release-candidate.yml`, run 37984182445) from `feat/project-viewer` commit `1836fd0`, rewrapped as the acceptance-identity copy and installed on a freshly created local Windows account (real WebView2 154), opened with the repo example project on the command line. `viewer-packaged.mjs` drives the packaged app over CDP; `viewer-packaged.ps1` is the lane launcher.

Result: 10 of 10 steps passed and the lane's production-state tripwire was clean (`viewer-packaged-result.json`, `viewer-packaged.lane-evidence.json`): the 3D view panel appeared, one real-size canvas was drawn with no graphics-failure alert, the object list and 9 camera buttons were present, selecting an object marked its row, mouse drags (all buttons, with modifiers), the wheel and keys changed nothing in the object list, leaving the page removed the canvas, no non-loopback request was made, no CSP or graphics-context problem was logged, and the project file bytes were unchanged.

What this does not prove: the build tested is `1836fd0`, not the final head. The later commits change one user-facing message string (the engine-capacity message), tests, docs and the generated measurements; they do not change the viewer's behavior. The installer is the acceptance-identity copy, not the production identity. Software versus GPU WebGL was not distinguished on this machine. Four earlier runs of this probe failed because of defects in the probe script itself (wrong route, no wait for the scene to load, wrong page chosen) and are not product results.
